## 前言 *Introduction*

这是一个早年间使用`MCReator`模组制作器制作的模组，由于众所周知的原因，MCR的项目不仅**管理混乱**，而且**开发处处受限**。  
在去年八月底发布第一版后，此模组就再无动静，转而投入`龙之生存（Dragon Survival）`附属模组的开发当中。  
时过境迁，又是一年过去，忽然想起来我还有一个沉睡的项目，便欲打开MCR查看。然而项目在岁月风吹雨打之下已然**无法打开**。  
于是我便利用`IDEA`软件将此项目重新导入，更下决心要将项目不堪入目的地方一一肃清，使它重新焕发生机。  

> 岩城乐事仓库，它重生于IDEA与AI的水火风霜之中，摒弃了MCR便利但却处处受限的轮椅身躯。

## 进度 *Pgogress*

**总体进度：大约50%**

## 分析 *Problem*

### `P0`一级问题 

- `MCR`编写导致项目内流程**冗余重复繁杂耦合度高**（最大的总的问题）；
- 多处**命名不规范**导致历史重大遗留问题（不需多言）；
- 作物方块采用多种不同方块替换实现，与原版单作物方块内置`生长阶段方块属性`区分方式迥异，导致实现不仅**复杂**效果还*不理想*；
- 调用别的模组的数据包加载配方等大量失效；
- `成就（Advancements）`多处**失效**，需要更新`物品ID`；
- `翻译语言文件`排序极度混乱

### `P1`二级问题

- 部分文本采用`硬编码`而非`翻译键`；
- 缺失大量标签，如食物类的C标签等；、
- 在`可选模组（Optional）`**未加载**时**未标注**使用这些模组的物品、容器的物品；
- 盖菜（芥菜）（Gaicai）和紫菜（Laver）两种无法正常在自然生成；
- 模组注册`物品`的代码多而不分类排列导致**可读性差**
- `食物效果`、`食用返回物`等本应可构建在`食物物品属性`内的方法被**外置调用流程**导致*舍近求远*；

### `P2`三级问题

- `食物药水效果`直接采用文本描述不优雅也不美观（除了`土烧`和`艾草汁`两物品）；
- 为食物手动添加`菜系`区分不优雅也不美观；
- 多个未添加`额外功能`、`描述`、`复杂属性`的普通物品也新建类导致物品类文件冗余不必；

## 重构 *Fix*

### `F0`一级要点

- 复杂的额外流程全部给你整合进本来调用的对应类里以简化；✅
- *（其他的暂时无需动作）*（尤其指）纹理图片均为极为难绷的拼音命名，需全数改为对应的物品、方块名；✅
- 作物类四大方块全换为**原版**的生长逻辑；✅
- 将`数据包加载`的其他模组配方等尽数修复；✅
- 替换`成就`里的`失效物品ID`；✅
- 重构`翻译语言文件`✅

### `F1`二级要点

- 将`食物药水效果`和`食用返回物`全部整合入`食物属性`内；✅
- 使所有文本均使用翻译键；✅
- 为物品、方块添加大量原版`minecraft标签`、`Neoforge`的`C标签`和`农夫乐事`的`farmersdelight`标签；✅
- 将食物的`药水效果`和`食用返回物`属性整合入`食物属性`当中；✅
- 修复芥菜和紫菜**无法自然生成**的问题；✅
- 将物品注册代码的`DDItems`进行排序分类；✅

### `F2`三级要点

- 通过java方法为食物自动添加`药水效果`描述；✅
- 将部分**完全无需**`额外拓展类`的物品类消去；✅
- 使用自定义标签分类不同食物菜系，并编写一个`Java文件`来根据标签自动加上`菜系名`；✅

## 畅想 *Prospect*

- 将部分品种作物替换入原版村庄的`菜地`中；
- 可在部分结构的`战利品箱`内搜索到本模组的`种子`、`原材料`甚至`食物`等内容；
- 实现`银耳（Tremella）`可以**自然生成**；
