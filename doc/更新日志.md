
> 此日志为岩城乐事（Duacan Delight）的重置版更新日志  
> 历经长达一个月的工作，将积攒许久的历史遗留问题尽数解决，终于迎来了复苏的曙光。  
> 虽然还有很多问题未解决，但已经是一个不错的开始了。

### `F0`一级

- 将**整个模组项目**全数由`IDEA`接管；
- 重构`翻译语言文件`
- 将`数据包加载`的其他模组配方等尽数修复（料理乐事除外）；
- 作物类四大方块全换为**原版**的生长逻辑；
- **重命名**极大量物品方块变量等；.
- 复杂的额外流程全部给合进本来调用的对应类里以简化；

### `F1`二级

- 使所有文本均使用`翻译键`避免`硬编码`；
- 为物品、方块添加大量原版`minecraft标签`、`Neoforge`的`C标签`和`农夫乐事`的`farmersdelight`标签以提供`兼容性`；
- 修复芥菜（Gaicai）和紫菜（Laver）**无法自然生成**的问题，紫菜现在如海带一样生成，芥菜则可以在村庄内农田里发现；

### `F2`三级

- 使用自定义标签分类不同食物`菜系`，并编写一个`Java文件`来根据标签自动加上`菜系名`；
- 通过java方法为本模组食物自动添加`药水效果`描述；
- 可在部分结构的`战利品箱`内搜索到本模组的`种子`等内容；


### F3（1.2.0-beta 后续）

- **新增工作方块：炸锅（Deep Frying Pan）**。移植自已停更的**随意乐事**（Casualness Delight，作者 Ginko）——原版炸锅在新版农夫乐事 / NeoForge 下已无法正常使用，因此暂时借用其模型、贴图与工作逻辑，后续会再重做；
  - 方块 ID 为 `duacan_delight:deep_frying_pan`，不属于原随意乐事的 `casualnessdelight` 命名空间；
  - 使用独立的 `duacan_delight:deep_frying` 配方类型（不占用原版营火烹饪配方），配方 JSON 与原版烹饪配方结构一致；
  - 加热方式与农夫乐事煎锅相同：放在点燃的火 / 灶台等加热源上，下方是带托盘的加热源时会显示托盘模型；
  - 右键放入食材、空手右键取出；泡在水里时会把锅内食材全部吐出；
  - 烹饪时长沿用原炸锅逻辑（`cookingtime` 全长烹饪，火焰附加每级 -5%，最低 3 秒），比煎锅慢；
  - 掉落时通过 `duacan_delight:copy_deep_frying_pan` 战利品函数保留方块实体记录的数据；
  - 附带 JEI 的“油炸”配方分类、背景贴图与炸锅催化方块。
- 4 条油炸配方（炸蒜末、炸豆腐、炸芋泥、炸猪油渣）由 `casualness_delight` 命名空间迁移至 `duacan_delight:recipe/deep_frying/`，并改写配方类型。


### F4（GUI 改造）

- **炸锅改造为带容器界面的工作方块**，工作逻辑随之重做：
  - 右键不再直接放入/取出物品，而是打开容器界面；
  - 界面参照农夫乐事厨锅：**1 个原料槽**（只接受能匹配油炸配方的物品，一次 1 个）、
    **1 个容具槽**（可放碗等容器，可选）、**1 个成品输出槽**（只能取出），外加玩家背包与快捷栏；
  - 烹饪完成后成品自动进入输出槽；若配方声明了 `container` 且容具槽里有对应容器，会消耗一个容器一起产出；
  - 界面含热源指示图标（悬浮显示"正在加热 / 需要热源"）与烹饪进度箭头；
  - 含水时不允许放入原料（会被立刻吐出），破坏方块时三格内容与未装容的成品全部掉落。
- **配方格式扩展**：油炸配方改用自带序列化器，在原有字段基础上新增**可选的 `container`** 字段（成品容器）。
  原有 4 条配方无需改写即可继续使用。
- 附带：JEI 油炸分类同步显示配方所需容器；新增炸锅的 GameTest（方块实体、原料校验、含水校验）。

> This changelog documents the updates for the remastered version of Duacan Delight.
> After a month-long effort, long-standing legacy issues have been resolved, and dawn of revival has finally arrived.
> Though many issues remain unresolved, this is already a promising start.

### `F0` Tier 1

- Migrated the **entire mod project** to be fully managed by `IDEA`;
- Refactored `translation language files`;
- Fully fixed the `datapack-loaded` recipes and other content from other mods (except Culinary Delight);
- Replaced the growth logic of the four major crop blocks with **vanilla** growth logic;
- **Renamed** a large number of item, block, and variable names;
- Consolidated all complex extra processes into the corresponding classes that originally invoked them for simplification;

### `F1` Tier 2

- All text now uses `translation keys` to avoid `hardcoding`;
- Added a large number of vanilla `minecraft tags`, Neoforge's `C tags`, and FarmersDelight's `farmersdelight` tags to items and blocks for improved `compatibility`;
- Fixed the issue where Gaicai and Laver **could not naturally generate** — Laver now generates like kelp, and Gaicai can be found in farmland within villages;

### `F2` Tier 3

- Used custom tags to classify different food `cuisines`, and wrote a `Java file` to automatically append `cuisine names` based on tags;
- Added `potion effect` descriptions to the mod's food items via Java methods;
- The mod's `seeds` and other content can now be found in `loot chests` within certain structures;

### F3 (after 1.2.0-beta)

- **New workstation: Deep Frying Pan**. Ported from the discontinued **Casualness Delight** (by Ginko) — its pan no longer works with current Farmer's Delight / NeoForge, so its model, textures and working logic are borrowed temporarily and will be reworked later;
  - Block ID is `duacan_delight:deep_frying_pan`, not the original `casualnessdelight` namespace;
  - Uses its own `duacan_delight:deep_frying` recipe type (it does not reuse vanilla campfire cooking), with recipe JSON matching vanilla cooking recipes;
  - Heated like the Farmer's Delight Skillet: place it on lit fire / stove or other heat sources; a tray model appears when the block below is a tray heat source;
  - Right-click to insert an ingredient, empty-hand right-click to take it out; being waterlogged makes it spit out everything inside;
  - Cooking time keeps the original pan logic (`cookingtime` full duration, Fire Aspect -5% per level, 3 s minimum), slower than the skillet;
  - Drops preserve the block entity data through the `duacan_delight:copy_deep_frying_pan` loot function;
  - Ships with a JEI "Deep Frying" recipe category, background texture and the pan as recipe catalyst.
- The four deep-frying recipes (fried grated garlic, fried tofu, fried cuma, fried pork cracklings) moved from the `casualness_delight` namespace to `duacan_delight:recipe/deep_frying/` with the new recipe type.

### F4 (GUI rework)

- **The deep frying pan is now a container-based workstation**, with its working logic reworked:
  - Right-clicking opens a container screen instead of inserting/removing items directly;
  - The screen follows the Farmer's Delight Cooking Pot layout: **one ingredient slot** (only items with a matching deep-frying recipe, one at a time), **one container slot** (bowls etc., optional), **one result slot** (take-only), plus the player inventory and hotbar;
  - Finished food goes into the result slot automatically; if the recipe declares `container` and the matching container is in the container slot, one is consumed together with the output;
  - The screen shows a heat indicator (tooltip "Heated / Requires heat") and a cooking progress arrow;
  - Ingredients are rejected while waterlogged (they would be spat out immediately), and breaking the block drops all three slots plus any uncontained result.
- **Recipe format extended**: deep-frying recipes now use a dedicated serializer that adds an **optional `container`** field (the serving container) on top of the existing fields. Existing four recipes need no rewriting.
- Also: the JEI deep-frying category now shows the required container; GameTests added for the pan (block entity, ingredient validation, waterlogged validation).
